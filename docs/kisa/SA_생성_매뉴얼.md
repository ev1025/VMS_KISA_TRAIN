# SA 생성 매뉴얼 — ARGOS VMS (지능형 CCTV 성능시험)

신청인: (주)엠알오디 · 제품: ARGOS VMS 1.1
신청 항목: 방화 · 침입 · 배회 · 쓰러짐 (일반분야 C, RGB/IR 00)

이 문서는 본시험에서 **진흥원 담당자가 직접 조작**하기 위한 절차서입니다.
화면에 보이는 것만 따라 하시면 되고, 명령어를 입력할 일은 없습니다.

---

## 1. 장비 구성

| | 장비 | 역할 |
|---|---|---|
| 송출 | 진흥원 PC (윈도우) | 시험영상 RTSP 전송 · VLC |
| 수신 | **신청인 장비 (NVIDIA Jetson Thor, 리눅스)** | 영상 분석 · SA XML 자동 저장 |

연결: 직결 케이블. 신청인 장비는 인터넷에 연결되지 않습니다.

### 저장 경로

안내서의 `c:\KISAresult` 는 윈도우 표기입니다. 신청인 장비는 리눅스라 드라이브 문자가 없으며,
같은 의미의 루트 경로를 사용합니다.

| 안내서 표기 | 신청인 장비 실제 경로 | 용도 |
|---|---|---|
| `c:\KISAresult` | **`/KISAresult`** | SA XML 자동 저장 |
| `c:\KISAmap` | **`/KISAmap`** | 영역파일(.map) |
| `c:\KISAlist` | **`/KISAlist`** | RTSP_streaming_list.xml |

세 경로 모두 화면 오른쪽 위에 항상 표시되므로 별도 확인이 필요 없습니다.

## 2. 시작하기

### 2-1. 신청인 장비 전원을 켜고 바탕화면의 **KISA 운영 콘솔** 을 실행합니다

브라우저가 열리며 아래 화면이 나옵니다. 주소는 `http://localhost:8770` 입니다.

```
 KISA 성능시험 운영 콘솔        SA /KISAresult   영역 /KISAmap (296)   목록 /KISAlist
 ┌──────────────┐  ┌────────────────────────────────────────┐
 │ 1 · 항목      │  │ 진행 상태                                │
 │ [방화] [침입]  │  │  ● 대기                                 │
 │ [배회] [쓰러짐] │  │    항목을 고르고 시작을 누르세요            │
 │ 2 · 방식      │  └────────────────────────────────────────┘
 │ [시험(RTSP)]  │
 │ RTSP 주소     │
 │ [   시작   ]  │
 │ 사전점검 실행  │
 └──────────────┘
```

### 2-2. **사전점검 실행** 을 누릅니다

`사전점검 통과` 가 나오면 정상입니다. 1분쯤 걸립니다.
실패가 나오면 시험을 진행하지 말고 신청인에게 알려 주십시오.

### 2-3. 영역파일과 목록파일을 넣습니다

1. 진흥원 PC 에서 `http://192.168.0.2:9999` 접속 → **Get video list**
2. 받은 `RTSP_streaming_list.xml` 을 신청인 장비의 `/KISAlist` 에 저장
3. 영역파일(.map)은 `/KISAmap` 에 저장 (침입·배회에만 사용)

화면 오른쪽 위 `목록 /KISAlist (N편)` 의 **N 이 실제 시험 편수와 같은지** 확인합니다.

## 3. 항목 하나 시험하기

> **항목은 반드시 하나씩 진행합니다.** 선택하지 않은 항목의 경보가 SA 에 섞이면
> 이벤트 종류 불일치로 오검출 처리되기 때문입니다.

### 3-1. 이전 결과를 비웁니다

SA 파일 목록 오른쪽의 **비우기** 를 누릅니다. 확인을 한 번 더 묻습니다.
앞 항목의 SA 가 남아 있으면 제출물에 섞입니다.

### 3-2. 항목과 방식을 고릅니다

- **1 · 항목** 에서 시험할 항목 하나 (방화 / 침입 / 배회 / 쓰러짐)
- **2 · 방식** 은 **시험 (RTSP)** 선택
- **RTSP 주소** 는 기본값 `rtsp://192.168.0.2:8554/` 를 그대로 둡니다
  (진흥원 PC 주소가 다르면 그 주소로 고쳐 주십시오)

### 3-3. **시작** 을 누릅니다

약 30초간 `준비` 가 표시됩니다. 모델을 올리는 중입니다.

### 3-4. 화면이 **`수신대기`** (노란색) 로 바뀌기를 기다립니다

> ### ● 수신대기 · 배회
> **이제 진흥원 PC 에서 Video load 를 누르세요**

**이 표시가 나온 뒤에** 진흥원 PC 에서 **Video load** 를 눌러 주십시오.
먼저 누르셔도 신청인 장비가 최대 30분간 기다리므로 문제는 없습니다.

### 3-5. 전송이 시작되면 자동으로 진행됩니다

화면이 `처리중` (파란색) 으로 바뀌고 지금 어느 영상 어디쯤인지 표시됩니다.

> ### ● 처리중 · 배회
> C00_001_0001.mp4 · 160초 지점

영상 하나가 끝날 때마다 **클립별 결과** 에 한 줄씩, **SA 파일** 에 파일 하나씩 늘어납니다.
**수 분간 숫자가 그대로인 것은 정상입니다.** 영상 한 편이 7~10분이기 때문입니다.
중지를 누르지 말아 주십시오.

### 3-6. 마지막 영상이 끝나면 `완료` (초록색) 가 표시됩니다

> ### ● 완료 · 배회
> SA 파일이 /KISAresult 에 저장됐습니다
> **SA 3건 저장 완료 (1377초)**

## 4. 제출 전 확인

### 4-1. 붉은 경고가 없어야 합니다

목록 편수와 처리한 편수가 다르면 아래 경고가 나옵니다.

> 목록은 30편인데 28편만 처리됐습니다. 클립 경계를 잘못 잡았을 수 있습니다. 제출 전에 확인하세요.

이 경고가 나오면 **그대로 제출하지 마시고** 신청인에게 알려 주십시오.
영상 전송이 중간에 끊겼거나 경계 판정이 어긋난 경우이며, 재시험이 필요합니다.

### 4-2. SA 파일 개수와 파일명을 확인합니다

**SA 파일** 목록에 시험 편수만큼 있고, 파일명이 영상 파일명과 같은지(확장자만 `.xml`) 봅니다.

### 4-3. `/KISAresult` 폴더를 제출합니다

## 5. 네 항목 모두 시험하는 경우

항목을 바꿀 때마다 **3-1 비우기부터** 다시 하고, 항목별 SA 를 따로 보관해 주십시오.
한 항목이 끝나기 전에 다른 항목을 시작할 수는 없습니다.

권장 순서는 없습니다. 항목별 소요 시간은 영상 길이에 비례하며, 분석은 전송과 동시에 끝납니다.

## 6. 문제가 생겼을 때

| 화면 | 뜻 | 조치 |
|---|---|---|
| `오류` (붉은색) | 비정상 종료 | **실행 출력** 내용을 신청인에게 알려 주십시오 |
| `수신대기` 에서 안 넘어감 | 영상이 도착하지 않음 | RTSP 주소 확인 후 Video load 재시도 |
| `그 밖의 출력 N줄` | 디코드 경고 | **정상입니다.** UDP 전송에서 늘 나옵니다 |
| 목록 편수 `(없음)` | 목록파일 미저장 | `/KISAlist` 에 목록파일을 넣어 주십시오 |

중지가 필요하면 **중지** 버튼을 누릅니다. 그때까지 저장된 SA 는 남습니다.

---

## 7. 참고 — 명령줄로 실행하는 경우

화면을 쓸 수 없을 때를 위한 대체 경로입니다. 통상은 사용하지 않습니다.

```
cd <제출 장비의 Kisa 폴더>        # 실제 경로는 장비의 .env 의 KISA_ROOT
./run.sh loitering rtsp://192.168.0.2:8554/
```

항목 이름: `fire` (방화) · `intrusion` (침입) · `loitering` (배회) · `falldown` (쓰러짐)

## 부록 · SA 파일 형식

영상 하나당 XML 하나가 같은 이름으로 생성됩니다.

안내서 붙임2 (6) 시스템 경보 p.45 의 예시 형태를 그대로 따릅니다.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<KisaLibraryIndex>
  <Library>
    <Clip>
      <Header>
        <AlarmEvents>1</AlarmEvents>
        <Filename>C00_001_0001.mp4</Filename>
      </Header>
      <Alarms>
        <Alarm>
          <StartTime>00:03:01</StartTime>
          <AlarmDescription>Loitering</AlarmDescription>
          <AlarmDuration>00:04:03</AlarmDuration>
        </Alarm>
      </Alarms>
    </Clip>
  </Library>
</KisaLibraryIndex>
```

- Header 속성값은 안내서 p.45 표대로 `<AlarmEvents>`(이벤트 발생 개수)와
  `<Filename>`(영상 파일명) 두 가지입니다.
- 이벤트가 없으면 `<AlarmEvents>0</AlarmEvents>` 과 빈 `<Alarms></Alarms>` 로 저장됩니다.
- `AlarmDescription` 은 항목별로 `FireDetection` · `Intrusion` · `Loitering` · `Falldown` 입니다.
- 파일명은 영상 파일명과 같고 확장자만 `.xml` 입니다.

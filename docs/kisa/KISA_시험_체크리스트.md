## 1. 평가 방식 요약 (안내서 §2·§3)
| 항목 | 값 |
|---|---|
| 합격 | F1 ≥ **90점** (항목별) |
| 정상검출 | AlarmDescription 일치 **and** StartTime ∈ [GT −2초, GT +10초] |
| 미검출 | GT 있는데 SA 없음 |
| 오검출 | 종류 불일치 **or** 창 밖 시각. 창 밖 경보는 **오검 + 미검 동시** (늦은 경보 < 무경보) |
| 방화 시각 | 연기/화염 발생 **+10초**. 최초 1건만 기록 |
| 침입 시각 | 몸 전체 진입. 다수면 **마지막 사람** |
| 배회 시각 | 몸 전체 진입 **+10초**(10초 이상 배회). 다수면 **마지막 사람** |
| 쓰러짐 시각 | 머리가 바닥에 닿는 시각. 다수면 **처음 사람**. 차량·조류 검출 금지 |
| 영상 | 1280×720 H.264 ≤10분, 날씨(눈·비·안개)·시간 6종(야간 IR 포함)·거리 3종 |
| SA 형식 | **안내서 p.45 예시 그대로**. `KisaLibraryIndex/Library/Clip/Header{AlarmEvents,Filename}/Alarms/Alarm{StartTime hh:mm:ss, AlarmDescription, AlarmDuration}`. 선언 `<?xml version="1.0" encoding="UTF-8"?>` |
| SA Header 속성값 | 안내서 p.45 표가 규정한 것은 **`<AlarmEvents>`(이벤트 발생 개수)·`<Filename>`(영상 파일명) 둘뿐**. GT 의 `Scenario`·`Dataset`·`Libversion`·`Weather`·`DetectArea` 는 진흥원 촬영 정보이지 SA 요구사항이 아니다(p.45 는 SA 와 GT 가 "유사하다" 고만 함). 2026-09-15 GT 뼈대로 바꿨다가 원문 확인 후 되돌림 |
| 복합 이벤트 | 한 SA 에 2개 이상이면 **발생 시각 순서대로** 기록 (p.46). 우리는 `--item` 게이팅이라 한 종류만 |
| Description | `FireDetection` `Intrusion` `Loitering` `Falldown` (대소문자·스펠링 엄격, FAQ 8) |

## 2. 시험장 절차 (§2 3·4단계)
- 진흥원 PC ↔ 우리 PC **직결 케이블**, 우리 PC 인터넷 불가, 백신 설치 필수
- 우리 PC에서 `http://192.168.0.2:9999` 접속 → **Get video list**(목록 파일 다운로드) → **Video load** → RTSP 실시간 전송 시작
- RTSP: VLC 2.1.5가 **같은 URL**(`rtsp://…:8554/`)로 클립을 **순차 재생(play-and-exit)** → 클립 사이 스트림 단절
- 영역파일 `c:\KISAmap\C00_XXX.map`, 목록 `c:\KISAlist\RTSP_streaming_list.xml`, SA 자동 저장 `c:\KISAresult\<영상명>.xml`
- 본시험: 제출 후 **수정 불가**, KISA 직원이 **우리 매뉴얼**로 조작, 종료 후 저장매체 **파기**

## 3.1 드라이런에서 발견해 고친 것 (2026-09-09, VLC 2.1.5 실측)
| 발견 | 영향 | 수정 |
|---|---|---|
| VLC 2.1.5 RTSP 서버가 **TCP 전송 거부**(`461 Unsupported transport`). 우리 소스는 `rtsp_transport=tcp` 고정 | 시험장에서 **프레임 0장 수신 → SA 전부 빈 파일 → 0점** | TCP 시도 후 실패 시 **UDP 자동 폴백**(`_av_backend`) |
| 스트림 pts 는 **클립 절대 재생위치**(늦게 붙어도 pts = 경과시각). 우리 소스는 첫 pts 를 0 으로 재설정 | 접속 지연(1~2초)만큼 모든 시각이 **앞당겨짐** → 창 하한(−2초) 침범 위험 | `abs_pts=True` (pts 그대로 사용). 다음 클립은 pts 가 작아져 **경계 자동 감지** |
| UDP 는 클립 끝에서 EOF 가 아니라 **타임아웃**으로 끊김. 예외 경로에서 세션을 넘기지 않았음 | 다음 클립 프레임이 **이전 파일명**으로 기록 → 이후 SA 연쇄 어긋남 | 프레임 수신 중 끊김 = 세션 경계로 처리, 타임아웃 2초 |
| 재시도 5회×1초 = 5초 | 우리 프로그램 켠 뒤 담당자가 Video load 누르기 전에 **포기** | 2초 × 900회(30분) |

## 3.2 Thor 배포본 실측에서 발견해 고친 것 (2026-09-15, 사내 PC ↔ Thor 직결, VLC 2.1.5)

배포 장비를 Thor 로 옮기고 **사내 PC 를 진흥원 PC 역할로 세워** 실제 RTSP 로 재현했다
(같은 서브넷, 시험장과 같은 VLC 2.1.5 로 순차 송출).
아래 셋은 전부 **오프라인 리허설로는 드러나지 않는다**(오프라인은 FileSource 라 RtspSource 를 한 줄도 안 지난다).

| 발견 | 영향 | 수정 |
|---|---|---|
| 컨테이너에 `lap` 없음. 배회 BoT-SORT 가 임포트한다 | **배회 즉사 → 0점.** 시험장은 인터넷 불가라 당일 설치 불가 | 이미지에 `lapx` 굽기 (`Dockerfile` → `kisa-runtime:1.2`) |
| `kisa_items.py` 가 `app.vision.frame_sources` 임포트 → 그 모듈이 `app.core.config` 를 부르는데 레포에 `app/core` 가 없음 | **`--rtsp` 전체 즉사.** nhn-yolo 에서도 안 됐다. 시험 당일 경로가 이것이다 | 앱 의존 없는 `tools/rtsp_source.py` 로 발췌 (원문 그대로) |
| PyAV 없으면 `default_backend` 가 **조용히** OpenCV 로 폴백. 그 경로는 pts 를 안 주고 전송방식도 못 고른다 | §3.1 의 절대 pts·TCP→UDP 폴백이 **통째로 무력화**. 로그 한 줄 말고는 표시가 없다 | 이미지에 `av`, **사전점검에서 PyAV 없으면 실행 차단** |
| **가짜 PTS 역전**: UDP 패킷 손실로 pts 가 순간 뒤로 감. 기존 판정 `t + 0.5 < last_t` 가 이를 새 클립으로 오인 | 클립 하나가 둘로 쪼개져 **이후 SA 파일명이 전부 한 칸씩 밀림**(= 위험 1번). 시각은 정확해서 로그를 안 까면 정상으로 보인다 | 경계 조건에 "클립 처음으로 복귀" 추가 (`PTS_BACK_MIN 5.0` **and** `PTS_START_MAX 5.0`), 기준 시각은 최대 pts 로 |

### Thor 실시간 처리 여유 (2026-09-15 실측, 한 표본 = 그 항목이 주기마다 돌리는 뷰 전부)

| 항목 | 해상도 | 뷰 | .pt GPU | .pt CPU | TRT FP16 | 표본 주기 | 여유(.pt GPU) |
|---|---|---|---|---|---|---|---|
| 쓰러짐 | 640 | 1 | 18.0ms | 528.8ms | 8.7ms | 100ms | 5.6배 |
| 배회 | 640 | 1 | 7.3ms | 88.6ms | 4.1ms | 500ms | 68배 |
| 침입 | 960 | 9 | 143.3ms | 2711.9ms | 94.1ms | 500ms | **3.5배** |
| 방화 | 640 | 6 | 24.5ms | 600.2ms | 22.0ms | 500ms | 20배 |

- **CPU 단독은 불가.** 쓰러짐 528.8ms 는 주기 100ms 의 5배, 침입 2.7초는 주기의 5배다.
- **TensorRT 는 쓰지 않는다.** 1.3~2.1배 빨라지지만 `.pt` 로도 여유가 충분하고, 엔진은
  (모델·해상도·배치)마다 다시 빌드해야 해서 제출 직전 변경 위험만 커진다. 엔진 파일은 삭제했다.
- 쓰러짐 실제 설정은 `pose_imgsz=1280`(90.00점) 이라 위 640 수치보다 느리다. 그래도 여유 안.
- 이 수치는 Thor(배포 장비) 기준이다. B200 속도는 배포 성능이 아니다.

### Thor 실시간 여유 — 배포 경로 실측 (2026-09-16)

위 표(2026-09-15)는 `scripts/bench_items.py` 로 잰 **순수 추론** 값이라 배포 경로와 다르다.
그 도구는 타일 대신 **원본 프레임을 뷰 수만큼 복제해 한 배치로** 넣고, NMS·트래커·SeqNet·판정기를 뺀다.
아래는 배포가 표본마다 실제로 부르는 것을 그대로 부른 값이다(`_kisa_port/tools/bench_thor.py`).

| 항목 | 뷰 | 중앙값 | 최악 | 표본 주기 | 여유 | 구성 |
| :-- | --: | --: | --: | --: | --: | :-- |
| 방화 | 12 | 106.8ms | 115.5ms | 500ms | 4.68배 | `fire_fog@640` + `fire_small@960`, 낱장 |
| 침입 | 9 | 103.5ms | 121.0ms | 500ms | 4.83배 | 3x3 타일@960 + 트래커 |
| **쓰러짐** | 1 | **58.2ms** | **63.7ms** | **100ms** | **1.72배** | 자세 1280 + SeqNet |
| 배회 | 1 | 28.1ms | 38.6ms | 500ms | 17.80배 | 전체프레임@640 + BoT-SORT |

측정 조건: Thor, `kisa-runtime:1.2` 컨테이너, GPU 점유 6%, 표본 15장(예열 3장), 배포 영상 실제 프레임.

- **네 항목 모두 주기 안에 들어온다. 최악값까지도 들어온다.**
- **쓰러짐이 가장 빠듯하다(1.72배).** 주기가 100ms 뿐인데 자세를 1280 으로 올렸기 때문이다.
  여기서 해상도를 더 올리거나 다른 계산을 얹으면 제일 먼저 깨지는 곳이 여기다.
- 방화 앙상블은 가중치 1벌 24.5ms 에서 2벌 106.8ms 가 됐지만 주기가 500ms 라 여유가 남는다.
- 09-15 표와 숫자가 다른 이유: 침입은 그때 **원본 프레임 9장**을 넣었는데 실제 타일은 511x336 이라 더 가볍다.
  배회는 반대로 그때 BoT-SORT 연결 비용이 빠져 7.3ms 로 나왔다. **두 표를 섞어 읽지 말 것.**

- 검사 `tools/test_rtsp_boundary.py` 5종(TCP 정상종료·UDP 타임아웃·섞임·**UDP 지터**·부분수신)으로 고정.
- 실측: 배회 3편 RTSP → SA 181 / 200 / 199초 = **오프라인과 초 단위 완전 일치**, 파일명 3/3 일치, 정검 3·미검 0·오검 0.

## 4. 위험·주의
1. **RTSP 경계 오판 → 파일명 연쇄 어긋남** = 이후 SA 전부 오검+미검. 드라이런 필수, 세션 수 ≠ 목록 수면 경고
2. **규칙 과적합**: 배포용 10/30/30/10편에 맞춘 파라미터. 인증용 100/300/300/100편은 비공개
3. 사람 모델 **차량·조류 오검** = 침입 오검. person 클래스만 사용하되 야간 IR에서 확인
4. 임계는 사전시험 결과 보고 확정 후 **설정 파일 잠금**(제출 후 수정 불가)
5. 저장매체 파기 → **전용 SSD**로 반입. 인터넷 불가 → pip/모델 다운로드 경로 전부 사전 준비

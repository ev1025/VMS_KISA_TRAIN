# B200 실험 서버 평가 절차 (nhn-yolo)

학습·실험 서버(B200)에서 **모델 하나를 어떤 숫자로 판단하는가**를 정한다.
채점 기준 자체(정상검출 창·F1 산출식·항목별 시작시각)는 [평가.md](평가.md), 시험장 절차는
[KISA_시험_체크리스트.md](KISA_시험_체크리스트.md), 제출용 조작 절차는 [SA_생성_매뉴얼.md](SA_생성_매뉴얼.md).

작업 위치는 실험 서버의 작업 저장소다(홈 디렉토리는 용량이 작아 쓰지 않는다).
경로는 `scripts/kisa_paths.py` 의 `KP.V` 에서 가져오고 문서·코드에 직접 적지 않는다.

---

## 1. 지표 세 가지와 서열

| 지표 | 무엇 | 내는 것 | 쓰임 |
|---|---|---|---|
| **채점 F1** | 배포 검증영상 편별 SA ↔ GT, 인증과 같은 규칙 | `_kisa_port/tools/kisa_items.py` (4항목), `score_kisa.py` (방화 단독) | **이것만이 합격 여부를 말한다** |
| 채점셋 mAP50 | 배포 검증영상 손라벨·전파 박스 기준 검출력 | `scripts/eval_map.py` → `results/<실험>/eval_map.json` | 모델 간 비교. F1 보다 민감 |
| 학습 val mAP | 학습 목록에서 뗀 val | ultralytics 학습 로그 | 참고만. 과거 누수 이력 있음 |

- 편수가 10~30 이라 **채점 F1 은 계단식**이다. 10편이면 66.67 · 82.35 · 88.89 · 94.74 밖에 안 나온다.
  1편 차이가 5~6점이므로 소수점 비교는 의미가 없다.
- mAP 가 올랐는데 F1 이 그대로인 일이 흔하다. **제출 판단은 F1 로만 한다.**

## 2. 절대 하지 말 것

- **배포 검증영상을 학습에 넣지 않는다.** 배경 하드네거티브로도 쓰지 않는다(그것도 누수다).
  `datasets.yaml` 의 `use: eval` 과 `build_trainset` 의 assert 로 막혀 있다. 라벨은 mAP 평가에만 쓴다.
- **규칙 스윕 값을 성적으로 보고하지 않는다.** 스윕한 F1 은 10~30편에 맞춘 값이라 거의 항상
  88.89 근처에서 포화되고 모델을 구분하지 못한다. 보고는 **고정 규칙(제출 설정) F1** 으로 한다.
- 스윕으로 파라미터를 고를 때는 **곡선이 평평한 구간**만 채택한다. 단일 첨점은 과적합이다.
  (침입 `gap` 1~4 전 구간 동일 → 채택 / 트랙 신뢰도 규칙 peak 0.90 단일 첨점 → 기각)

## 3. 실행

### 3.1 큐로 돌리기 (학습 → 평가 자동)

```bash
python scripts/exp_queue.py --config configs/<큐>.yaml
```

`exp_queue.py` 가 학습 후 `eval_map()` · `score()` · `score_person()` 을 이어서 돌리고
`results/<실험>/meta.json` 에 설정을 남긴다. **실험 imgsz 가 평가에도 그대로 전달된다**
(예전에 평가가 640 으로 고정돼 해상도 실험이 통째로 무의미했던 적이 있다).

### 3.2 4항목 채점 (오프라인)

```bash
python _kisa_port/tools/kisa_items.py --item loitering \
    --videos <mp4 폴더> --maps <map 폴더> --gt <GT 폴더> --out <SA 폴더>
```

- `--item` 은 하나만. 다른 항목 경보가 섞이면 이벤트 종류 불일치로 오검이다.
- 학습 실험 가중치로 채점하려면 `--person-weights` (침입·배회) · `--fire-weights` (방화),
  해상도는 `--person-imgsz`.
- GT 를 주면 편별 판정과 점수까지 출력한다.

### 3.3 방화만 빠르게

```bash
python score_kisa.py --pt runs/<실험>/weights/best.pt
```

### 3.4 검출 mAP

```bash
python scripts/eval_map.py fire --exp <실험명>      # 또는 --all
python scripts/eval_map.py person --exp <실험명>
```

### 3.5 추론 속도

```bash
python scripts/bench_exp.py --exp <실험명>          # results/<실험>/bench.json
```

`.pt` · onnx × CPU · GPU 4칸. **B200 속도는 배포 성능이 아니다.** 실배포는 Thor(Jetson)이고
그쪽 실측은 `Desktop/Project/Kisa/bench_thor*.json` 에 있다.

## 4. 경로·상수

경로와 상수는 **`scripts/kisa_paths.py` 한 곳에서만** 정의한다. 새 스크립트에서 경로를
문자열로 다시 적지 않는다. 규칙은 [docs/file_path.md](../file_path.md).

| 이름 | 뜻 |
|---|---|
| `KP.V` | 저장소 루트 (`VMS_ROOT` 환경변수로 덮어쓰기 가능) |
| `KP.DEPLOY_VAL` | 배포 검증영상 (**채점 전용**) |
| `KP.ZONE_MAPS` | 영역파일 |
| `KP.videos(항목)` | 항목별 mp4 목록 |
| `KP.SAMPLE_STRIDE_S` | 표본 주기 0.5초 |
| `KP.DEFAULT_IMGSZ` | 640 |

산출물은 `results/<실험명>/` 아래. 실험명·설정은 `meta.json` 에 넣고 폴더명에 담지 않는다.

## 5. 결과 보기

대시보드 `dash_v2` (8890, ssh 포트포워딩). 실험 기록 표는
**해상도 · 입력데이터 · 기법** 이 같은 것끼리 묶이고, 토글 안에 모델별 성능과 규칙 스윕이 들어간다.
속도는 `bench.json` 에서 `.pt`/onnx × CPU/GPU 로 표시된다.

## 6. 자주 밟은 함정

| 함정 | 증상 | 대응 |
|---|---|---|
| 평가 imgsz 하드코딩 | 해상도 실험이 전부 640 으로 평가돼 무의미 | `eval_map.py`·`score_kisa.py` 에 실험 imgsz 전달 |
| `except Exception` 이 예외를 삼킴 | NumPy 2.0 에서 `ndarray.ptp()` 제거 → 조용히 −1/0 산출, 결론 두 건 철회 | 예외는 출력한다. `np.ptp()` 사용 |
| 학습 해상도 ≠ 추론 해상도 | 640 으로 파인튜닝한 모델은 추론 해상도를 올리면 오히려 나빠짐. 사전학습 pose 모델은 올리면 좋아짐 | 모델별로 따로 확인 |
| 대시보드 중복 제거를 점수로 묶음 | 설정이 다른 17개 실험이 한 줄로 합쳐짐 | `item + name` 으로 묶는다 |
| 결과 로그를 엉뚱한 파일에 | 대시보드에 안 뜸 | `logs/queue/val_*.log` 규칙 유지 |
| `pkill -f` 패턴이 자기 셸·남의 프로세스를 잡음 | ssh 끊김, 무관한 프로세스 종료 | 대괄호 트릭 + `-u` 로 사용자 한정, 명령줄에 패턴 문자열을 중복해 쓰지 않는다 |

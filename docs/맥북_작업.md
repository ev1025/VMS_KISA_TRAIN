# 맥북에서 작업하기

애플 실리콘 맥북으로 라벨·전파·학습을 해보려는 경우의 준비물과 한계를 적는다.
맥북의 클로드코드가 이 문서만 보고 진행할 수 있게 썼다.

세 갈래가 있다.

| | 무엇 | 옮길 데이터 | 전파 속도 |
|---|---|---|---|
| 1 | 서버 대시보드에 터널로 붙는다 | **없음** | B200 GPU |
| 2 | 맥북에서 대시보드를 돌린다 | 영상 + 라벨 | 애플 GPU(MPS) |
| 3 | 맥북에서 학습한다 | 학습셋 + 사전학습 가중치 | — |
| 4 | 사람(침입·배회) 악천후 시험 | 3.5 GB | — |

**어느 갈래든 0번(데이터 받기)이 먼저다.** 집에서는 서버에 못 붙으므로 사무실에서 받아 두지 않으면 아무것도 못 한다.

## 0. 먼저 할 일 — 사무실에서 데이터를 받아 둔다

**집에서는 서버에 못 붙는다.** NHN 방화벽에 회사 IP 만 등록돼 있고 집 IP 는 열 수 없다(권한이 없다).
그래서 1번은 사무실에서만 되고, 2·3번은 **데이터를 미리 받아 둬야** 집에서 돌아간다.
맥북 작업의 순서는 무조건 이것부터다. 받아 두지 않으면 집에서 할 수 있는 일이 없다.

| 언제 | 어디서 | 무엇 |
|---|---|---|
| 사무실 | 회사 IP | 아래 `mac_pull.sh` 로 받는다 |
| 집 | 맥북 단독 | 대시보드·학습을 돌린다. 서버가 필요 없다 |

### 받는 법

```bash
git clone git@github.com:ev1025/VMS_KISA_TRAIN.git vms && cd vms

./scripts/mac_pull.sh 라벨             # 손라벨                    30 MB
./scripts/mac_pull.sh 학습             # 손라벨 + 학습셋           4.5 GB
./scripts/mac_pull.sh 학습 --베이스     # + aihub71751_48k         20 GB
./scripts/mac_pull.sh 영상 악천후       # 손라벨 + 악천후 45편      12 GB
./scripts/mac_pull.sh 영상 방화         # 손라벨 + 방화 75편        24 GB
```

**누적이 아니다.** 손라벨·`configs/datasets.yaml` 은 어느 모드에서나 받지만,
학습셋은 `학습` 에서만, 영상은 `영상` 에서만 온다. 라벨도 하고 학습도 할 거면 두 번 돌린다.

```bash
./scripts/mac_pull.sh 영상 악천후 && ./scripts/mac_pull.sh 학습
```

회사 IP 가 아니면 서버 연결 확인에서 먼저 알려 주고 멈춘다. `rsync` 라 중간에 끊겨도 다시 돌리면 이어받는다.

## 2. 맥북에서 대시보드 돌리기 (집에서는 이것)

집 IP 로는 서버에 못 붙으므로 집에서 작업하려면 이 방법뿐이다.
사무실에서 `./scripts/mac_pull.sh` 로 받아 두면 집에서는 서버가 필요 없다.

### 옮길 것

`./scripts/mac_pull.sh 영상 악천후` 면 손라벨과 영상 45편이 들어온다(0번 참고).
사무실에서 받아 두면 집에서는 서버가 필요 없다.

### 설치

```bash
python3 -m venv .venv
.venv/bin/pip install opencv-python numpy pyyaml          # 손라벨
.venv/bin/pip install torch torchvision transformers==5.17.0   # 전파까지 하려면
```

### 실행

```bash
cd dash_v2 && ../.venv/bin/python -u serve_kisa.py
```

`http://127.0.0.1:8890`. 영상을 새로 넣었으면 화면에서 캐시 갱신을 누른다.

### 전파(SAM2)가 맥에서 어떻게 도나

`torch_device()` 가 `cuda → mps → cpu` 순으로 고른다. 맥에서는 MPS 가 잡힌다.
MPS 가 지원 안 하는 연산은 `PYTORCH_ENABLE_MPS_FALLBACK=1` 로 CPU 에 흘린다.

```bash
export PYTORCH_ENABLE_MPS_FALLBACK=1
```

모델은 `facebook/sam2.1-hiera-small` 이고 처음 쓸 때 내려받는다(인터넷 필요, 한 번만).

**엔비디아보다 느리다.** 한 번에 객체를 여럿 전파하지 말고 나눠 돌린다.
맥에서 검증한 적이 없으니 처음에는 짧은 구간으로 시험한다.

### 끝나면 서버로 합친다

맥북에서 만든 라벨은 맥북 안에만 있다.

```bash
scp -r data/학습데이터/손라벨 nhn-yolo:/tmp/mac_in/
ssh nhn-yolo "cd /NHNHOME/WORKSPACE/26mss002_E3/vms && .venv/bin/python scripts/merge_labels.py /tmp/mac_in --dry"
```

`--dry` 로 무엇이 들어갈지 먼저 본다. 괜찮으면 빼고 다시 돌린다.
같은 클립을 양쪽에서 만졌으면 충돌로 남고, 맥북 값을 쓰려면 `--take-incoming` 을 붙인다.

**겹치는 박스는 들어온 쪽(맥북)이 이긴다.** 같은 프레임·같은 클래스에서 IoU 0.5 이상이면
방금 다시 그린 것을 남기고 서버에 있던 옛 박스를 뺀다. 합칠 때 자동으로 돈다.
예전에는 넓이가 큰 쪽을 남겨서, 옛 박스가 더 크면 새로 그린 것이 지워졌다(2026-09-22 고침).

객체 번호는 1~10 을 쓴다(숫자키 `1`~`9`, `0` 이 10번). 번호가 겹쳐도 학습에는 영향이 없다.
YOLO 라벨에는 번호가 안 들어간다.

## 3. 맥북에서 학습하기

**먼저 알아야 할 것.** 방화 한 번 학습에 B200(183GB) 으로 7.8시간이 걸린다. 24만 장을 60에폭 돌린다.
맥북으로 같은 것을 재현할 수 없다. 데이터를 줄이고 에폭을 줄여 **경향만** 보는 용도다.

### 지난 실험이 얼마였는지

`results/` 는 깃에 없지만 점수 요약은 있다. 클론만 해도 읽을 수 있다.

```
results/SUMMARY.md
```

방화 46건·사람 49건의 최고점과 배포 점수, 변별력 있는 세 편(195·216·272)의
개별 성패가 들어 있다. 맥북에서 돌린 결과를 여기와 비교하지 않는다(데이터도 에폭도 다르다).

### 데이터

`./scripts/mac_pull.sh 학습` 으로 받아 둔 것을 쓴다. 내역과 크기는 **0번**에 있다.
맥북에서는 `aihub71751_48k`(15GB) 를 빼고 4.5GB 로 시작한다.

### 맥에서 학습이 되긴 하나

ultralytics 는 `device="mps"` 를 받는다. 다만

- **배치를 크게 못 잡는다.** 통합 메모리를 GPU 와 CPU 가 나눠 쓴다. 16GB 맥이면 960 해상도에 batch 4~8 수준이다
- **`multi_scale` 은 끄는 편이 낫다.** 크기가 바뀔 때마다 메모리가 튄다
- 러너(`scripts/exp_queue.py`)는 B200 전제로 짜여 있다(VRAM 게이트·잡 관리). 맥에서는 `model.py train` 을 직접 부르는 편이 간단하다

경향만 보려면 이런 식으로 시작한다.

```bash
.venv/bin/python model.py train --models yolo11s \
  --data <data.yaml> --device mps --imgsz 640 --batch 4 --epochs 10 --workers 4
```

`data.yaml` 은 `_exp/<실험>/` 에 러너가 만드는 것과 같은 형식이다. 직접 쓰려면
`scripts/exp_queue.py` 의 `build_lists()` 를 보고 train.txt·val.txt·data.yaml 세 개를 만든다.

### 넘지 말아야 할 선

- **채점셋(`kisa_배포_검증영상`)은 어떤 경우에도 학습에 넣지 않는다.** 배경으로도 안 된다
- **`human_fire` 를 쓰지 않는다.** 채점 10편 2,520장이 그 안에 들어 있다(2026-09-22 확인).
  `extras`·`oversample` 어디에도 넣으면 안 된다. `scripts/leak_check.py` 가 이름을 대며 막는다
- 맥북에서 나온 점수는 서버 점수와 비교하지 않는다. 데이터도 에폭도 다르다

라벨은 맥북 안에 쌓이므로, 끝나면 **2번의 '끝나면 서버로 합친다'** 를 따라 올린다.

`clip_state.json` 의 완료/전파 표시도 같이 올려야 한다.
**이것이 빠지면 `build_trainset --marks` 가 새로 라벨한 편을 통째로 걸러낸다.**
2026-09-23 에 악천후가 이 때문에 +130장만 들어간 일이 있었다.

### 왜 COCO 를 안 받나

베이스 `trainset_person_20260915` 은 서버에서 19GB 인데 속이 이렇다.

| | 장수 |
|---|---|
| `open_coco` (`images_train2017_*.jpg`, 3840x2160) | 117,266 |
| KISA 영상 프레임 (`C*.jpg` 등) | 1,528 |

19GB 인 이유는 COCO 4K 이미지 때문이고, 우리 자료는 254MB 뿐이다.
COCO 는 공개 데이터라 필요하면 맥북에서 직접 받으면 된다.
`mac_pull.sh` 가 `train.txt`·`val.txt` 에서도 COCO 줄을 지운다.
**안 지우면 없는 파일을 찾다가 학습이 죽는다.**

맥북에서 짧게 돌릴 때는 COCO 가 손라벨 신호를 묻으므로 안 넣는 편이 낫다.

### 학습 돌리는 법

```bash
export PYTORCH_ENABLE_MPS_FALLBACK=1
.venv/bin/python model.py train --models yolo11s \
  --data _exp/mac_person/data.yaml --device mps \
  --imgsz 640 --batch 4 --epochs 10 --workers 4 --project _exp/mac_person/runs
```

러너(`scripts/exp_queue.py`)는 쓰지 않는다. B200 전제라 VRAM 게이트에 걸린다.
`multi_scale` 은 끈다. 맥 통합메모리에서 크기가 바뀔 때마다 메모리가 튄다.

### 점수를 재려면

이미지 mAP(`evalset_person`)와 **인증 점수는 다른 것**이다. 실제 F1 은 채점기를 돌려야 나온다.

채점기는 `_kisa_port/tools/kisa_items.py` 다. 서버에서 `scripts/exp_queue.py` 의
`score_person()` 이 그것을 그대로 부른다. 그 코드를 보고 같은 인자로 부르면 된다.

**항목마다 해상도가 다르다.** 이것을 틀리면 점수가 엉뚱하게 나온다.

| 항목 | 방식 | 해상도 |
|---|---|---|
| 침입 | 3x3 타일 + 자체 트래커 | 960 |
| 배회 | 전체 프레임 + BoT-SORT | 640 |

`person_v2` 를 배회에 960 으로 재면 93.10 이 79.31 로 떨어진다. 배율이 안 맞아서지
모델이 나빠서가 아니다(2026-09-16 실측).

**시간을 각오해야 한다.** 서버(B200)에서도 침입 30편 + 배회 30편에 10~40분이다.
맥북 MPS 는 훨씬 느리고, 배회는 전체 프레임에 추적까지 돌아 **여러 시간** 걸린다.
한 항목씩 나눠 돌리는 편이 낫다.

### 채점 영상은 학습에 넣지 않는다

`kisa_배포_검증영상` 은 **채점 전용**이다. `configs/datasets.yaml` 에 `use: eval` 로
박혀 있어 학습셋 빌더가 자동으로 뺀다. 배경으로도, 하드네거티브로도 넣지 않는다.
학습셋 `meta.json` 에 `채점클립 검사: 누수 0` 이 찍히는지 확인한다.

### 알고 시작할 것 — 640 으로는 안 보이는 실패가 있다

서버 학습은 **117,529장 · imgsz 1280 · 60에폭**이다. 맥북으로 재현할 수 없다.

침입·배회 실패는 **화면 높이 5%(34~50px) 소형 사람**에 몰려 있다.
640 으로 줄이면 그 사람이 17~25px 이 되어 **정작 보고 싶은 실패가 재현되지 않는다.**

| 맥북에서 되는 것 | 맥북에서 안 되는 것 |
|---|---|
| 악천후를 넣으면 방향이 나아지나 | 서버 점수와 그대로 비교 |
| 학습이 도는가·라벨이 맞는가 | 소형 사람 실패 재현 |
| 데이터 조합을 빠르게 훑기 | 제출 모델 고르기 |

여유가 되면 `--imgsz 960` 으로 한 번 더 돌려 640 과 견줘 본다.
소형 사람 문제가 해상도에서 오는지 데이터에서 오는지 그 차이로 보인다.

### 쓰면 안 되는 학습셋

**`person_mask_hn_paste_20260919` 은 쓰지 않는다.** 2026-09-20 에 철회됐다
(`docs/EXPERIMENTS.md` 4.18). 소형 사람을 잘라 붙인 합성인데, 붙인 자국이 도메인 이동을

침입이 76.00 으로 내려갔다. `configs/datasets.yaml` 80줄에 '사용 안 함' 으로 적혀 있다.

## 토르는 학습용이 아니다

토르(Jetson)는 **배포 경로 채점**에 쓴다. 학습은 B200 에서만 한다.
채점 도구는 `scripts/thor_score.py` 이고 작업 PC 에서 돌린다
(서버와 토르는 서로 못 붙는다. 양쪽에 붙을 수 있는 것은 사내망의 작업 PC 뿐이다).
맥북에서는 토르에 못 붙는다. 토르는 사내망 사설 IP 다.

## 어느 것부터 하나

**무엇을 하든 0번(데이터 받기)을 사무실에서 먼저 한다.**
**사무실에 있으면 1번**이 가장 빠르다. 옮길 것이 없고 전파가 B200 에서 돈다.
**집에서 하려면 2번**뿐이다. 그 전에 사무실에서 `./scripts/mac_pull.sh` 로 받아 둬야 한다.
3번(학습)은 경향만 보는 용도다. B200 한 번이 7.8시간인 것을 맥북으로 재현할 수 없다.
**사람(침입·배회) 작업은 4번**에 따로 적었다. 지금 맥북에서 할 일이 그것이다.

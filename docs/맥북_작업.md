# 맥북에서 작업하기

애플 실리콘 맥북으로 라벨·전파·학습을 해보려는 경우의 준비물과 한계를 적는다.
맥북의 클로드코드가 이 문서만 보고 진행할 수 있게 썼다.

세 갈래가 있다.

| | 무엇 | 옮길 데이터 | 전파 속도 |
|---|---|---|---|
| 1 | 서버 대시보드에 터널로 붙는다 | **없음** | B200 GPU |
| 2 | 맥북에서 대시보드를 돌린다 | 영상 + 라벨 | 애플 GPU(MPS) |
| 3 | 맥북에서 학습한다 | 학습셋 + 사전학습 가중치 | — |

## 먼저 — 집에서는 서버에 못 붙는다 (2026-09-22)

NHN 방화벽에 **회사 IP 만** 등록돼 있다. 집 IP 는 열 수 없다(권한이 없다).
그래서 1번은 사무실에서만 된다. 집에서 작업하려면 **2·3번뿐이고, 데이터를 미리 받아 둬야 한다.**

| 언제 | 어디서 | 무엇 |
|---|---|---|
| 사무실 | 회사 IP | `./scripts/mac_pull.sh` 로 한 번에 받는다 |
| 집 | 맥북 단독 | 대시보드·학습을 돌린다. 서버가 필요 없다 |

```bash
git clone git@github.com:ev1025/VMS_KISA_TRAIN.git vms && cd vms
./scripts/mac_pull.sh 라벨          # 손라벨 30MB
./scripts/mac_pull.sh 학습          # + 학습셋 4.5GB
./scripts/mac_pull.sh 영상 악천후    # + 영상 45편 12GB
```

`rsync` 라 중간에 끊겨도 다시 돌리면 이어받는다. 회사 IP 가 아니면 스크립트가 먼저 알려주고 멈춘다.

## 1. 서버 대시보드에 붙기 (권장)

전파가 B200 에서 돌고 맥북은 그림만 받는다. 옮길 데이터가 없다.

### 한 번만

키 파일(`yolo_key`)을 맥북 `~/.ssh/yolo_key` 에 둔다. 저장소에는 없으니 사람이 옮겨야 한다.

```bash
chmod 600 ~/.ssh/yolo_key
cat >> ~/.ssh/config <<'EOF'

Host nhn-yolo
    HostName 59.150.32.1
    Port 48304
    User startup022
    IdentityFile ~/.ssh/yolo_key
    IdentitiesOnly yes
    ServerAliveInterval 30
EOF
```

### 쓸 때마다

```bash
ssh -N -L 8890:127.0.0.1:8890 nhn-yolo    # 이 창은 켜 둔다
```

브라우저로 `http://127.0.0.1:8890`.

### 실측 (2026-09-22, 사내망 → 원격 서버)

| | |
|---|---|
| 첫 화면 | 10 KB · 0.01초 |
| 클립 목록 45편 | 0.06초 |
| 프레임 폭 960 | 102 KB · 0.07초 |
| 프레임 폭 1280 | 240 KB · 0.14초 |

프레임은 서버가 캐시한다. 같은 프레임을 다시 열면 디코딩 없이 온다.

### 주의

- 대시보드는 `127.0.0.1` 에만 열려 있다. 터널 없이는 못 붙는다(그렇게 두는 것이 맞다)
- 라벨은 **서버에 바로 쌓인다.** 나중에 합칠 필요가 없다
- 같은 클립을 두 곳에서 동시에 만지지 않는다

## 2. 맥북에서 대시보드 돌리기

인터넷이 없는 곳에서 작업해야 할 때만 고른다. 1번이 되면 할 이유가 없다.

### 옮길 것

| | 크기 | 비고 |
|---|---|---|
| 코드 (`dash_v2` `configs` `scripts`) | 4 MB | `_cache` 는 뺀다(다시 만들어진다) |
| 손라벨 (`data/학습데이터/손라벨`) | 30 MB | |
| 영상 | 고른 만큼 | 아래 표 |

영상은 `data/원본데이터/<묶음>/` 통째로 넣는다. 이름이 `configs/datasets.yaml` 의 항목과 같아야 한다.

| 묶음 | 크기 | 무엇 |
|---|---|---|
| `KISA_악천후_사람` | 12 GB | 눈7·안개3·비13. **지금 라벨할 것** |
| `kisa_연구개발_방화영상` | 24 GB | 방화 75편 |
| `kisa_연구개발_사람영상` | 257 GB | 사람 825편. 맥북에 넣을 크기가 아니다 |

### 설치

```bash
python3 -m venv .venv
.venv/bin/pip install opencv-python numpy pyyaml          # 손라벨
.venv/bin/pip install torch torchvision transformers==5.17.0   # 전파까지 하려면
```

### 실행

```bash
cd dash_v2 && ../.venv/bin/python -u serve_kisa.py
```

`http://127.0.0.1:8890`. 영상을 새로 넣었으면 화면에서 캐시 갱신을 누른다.

### 전파(SAM2)가 맥에서 어떻게 도나

`torch_device()` 가 `cuda → mps → cpu` 순으로 고른다. 맥에서는 MPS 가 잡힌다.
MPS 가 지원 안 하는 연산은 `PYTORCH_ENABLE_MPS_FALLBACK=1` 로 CPU 에 흘린다.

```bash
export PYTORCH_ENABLE_MPS_FALLBACK=1
```

모델은 `facebook/sam2.1-hiera-small` 이고 처음 쓸 때 내려받는다(인터넷 필요, 한 번만).

**엔비디아보다 느리다.** 한 번에 객체를 여럿 전파하지 말고 나눠 돌린다.
맥에서 검증한 적이 없으니 처음에는 짧은 구간으로 시험한다.

### 끝나면 서버로 합친다

맥북에서 만든 라벨은 맥북 안에만 있다.

```bash
scp -r data/학습데이터/손라벨 nhn-yolo:/tmp/mac_in/
ssh nhn-yolo "cd /NHNHOME/WORKSPACE/26mss002_E3/vms && .venv/bin/python scripts/merge_labels.py /tmp/mac_in --dry"
```

`--dry` 로 무엇이 들어갈지 먼저 본다. 괜찮으면 빼고 다시 돌린다.
같은 클립을 양쪽에서 만졌으면 충돌로 남고, 맥북 값을 쓰려면 `--take-incoming` 을 붙인다.
같은 불에 두 번 그려진 박스는 합칠 때 자동으로 하나로 줄인다.

## 3. 맥북에서 학습하기

**먼저 알아야 할 것.** 방화 한 번 학습에 B200(183GB) 으로 7.8시간이 걸린다. 24만 장을 60에폭 돌린다.
맥북으로 같은 것을 재현할 수 없다. 데이터를 줄이고 에폭을 줄여 **경향만** 보는 용도다.

### 코드

```bash
git clone git@github.com:ev1025/VMS_KISA_TRAIN.git vms
```

`data/` `model/` `runs/` 는 깃에 없다(용량). 아래를 따로 받는다.

### 학습셋 (방화 기준)

| 이름 | 크기 | 자리 |
|---|---|---|
| `aihub71751_48k` | **15 GB** | `data/원본데이터/` |
| `fasdd_yolo` | 725 MB | `data/학습데이터/` |
| `fasdd_snowfog` | 30 MB | `data/학습데이터/` |
| `wildfire_pos_yolo` | 487 MB | `data/학습데이터/` |
| `wildfire_fog_neg` | 51 MB | `data/학습데이터/` |
| `fire_mask_hn_fog_20260919` | 1.1 GB | `data/학습데이터/` |
| `handset_fire_hand_20260922` | 417 MB | `data/학습데이터/` |
| `handset_fire_prop_20260922` | 609 MB | `data/학습데이터/` |
| `handset_fire_all_20260922` | 1.1 GB | `data/학습데이터/` |
| | **약 20 GB** | |

**맥북에서는 `aihub71751_48k`(15GB, 39,003장) 를 빼는 편이 낫다.** 그것만 빼면 4.5GB 로 줄고,
손라벨 중심으로 경향을 보는 데는 충분하다. 큐 yaml 의 `base_frac` 으로 비율을 낮춰도 된다.

### 사전학습 가중치

```
model/pretrained/     787 MB      yolo11n/s/m/l/x 등
```

`yolo11s.pt` 하나만 받아도 된다(약 19MB).

### 받는 법

`./scripts/mac_pull.sh 학습` 하나면 끝난다. 손으로 하려면 아래와 같다.

```bash
# 코드
git clone git@github.com:ev1025/VMS_KISA_TRAIN.git vms && cd vms

# 학습셋 (필요한 것만)
R=nhn-yolo:/NHNHOME/WORKSPACE/26mss002_E3/vms
mkdir -p data/학습데이터 data/원본데이터 model/pretrained
for n in fasdd_snowfog wildfire_fog_neg handset_fire_hand_20260922 \
         handset_fire_prop_20260922 handset_fire_all_20260922 fire_mask_hn_fog_20260919; do
  rsync -a --info=progress2 "$R/data/학습데이터/$n" data/학습데이터/
done
rsync -a "$R/model/pretrained/yolo11s.pt" model/pretrained/
```

`rsync` 가 중간에 끊겨도 이어받는다. `scp` 는 처음부터 다시 받는다.

### 맥에서 학습이 되긴 하나

ultralytics 는 `device="mps"` 를 받는다. 다만

- **배치를 크게 못 잡는다.** 통합 메모리를 GPU 와 CPU 가 나눠 쓴다. 16GB 맥이면 960 해상도에 batch 4~8 수준이다
- **`multi_scale` 은 끄는 편이 낫다.** 크기가 바뀔 때마다 메모리가 튄다
- 러너(`scripts/exp_queue.py`)는 B200 전제로 짜여 있다(VRAM 게이트·잡 관리). 맥에서는 `model.py train` 을 직접 부르는 편이 간단하다

경향만 보려면 이런 식으로 시작한다.

```bash
.venv/bin/python model.py train --models yolo11s \
  --data <data.yaml> --device mps --imgsz 640 --batch 4 --epochs 10 --workers 4
```

`data.yaml` 은 `_exp/<실험>/` 에 러너가 만드는 것과 같은 형식이다. 직접 쓰려면
`scripts/exp_queue.py` 의 `build_lists()` 를 보고 train.txt·val.txt·data.yaml 세 개를 만든다.

### 넘지 말아야 할 선

- **채점셋(`kisa_배포_검증영상`)은 어떤 경우에도 학습에 넣지 않는다.** 배경으로도 안 된다
- **`human_fire` 를 쓰지 않는다.** 채점 10편 2,520장이 그 안에 들어 있다(2026-09-22 확인).
  `extras`·`oversample` 어디에도 넣으면 안 된다. `scripts/leak_check.py` 가 이름을 대며 막는다
- 맥북에서 나온 점수는 서버 점수와 비교하지 않는다. 데이터도 에폭도 다르다

## 어느 것부터 하나

라벨·전파가 목적이면 **1번만 하면 된다.** 옮길 것이 없고 가장 빠르다.
2번은 인터넷이 없는 자리에서만, 3번은 경향을 직접 만져 보고 싶을 때만 고른다.

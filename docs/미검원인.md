## 2. 미검 5편 — 원인별 분류

### 결론부터: 5편 전부 "데이터 문제" 다. 규칙으로는 못 고친다.

다섯 편 모두 **경보가 아예 안 울렸다**(`sa=None`). 늦게 울린 게 아니라 안 울렸다.
즉 "언제 울릴지 정하는 규칙" 의 문제가 아니라 **"사람을 못 봤다"** 는 문제다.

| 편 | 항목 | 장면 | 구역 안 최고 신뢰도 | 문턱 | 원인 |
| :-- | :-- | :-- | --: | --: | :-- |
| `C00_249_0003` | 침입 | 주간 설경, 울타리 뒤 원경 | 0.19 | 0.45 | 원경 소형(22~36px) |
| `C00_275_0001` | 침입 | 야간 안개, 담장 위 | 0.41 | 0.45 | 원경 소형(17~36px) + 저대비 |
| `C00_255_0001` | 침입 | **야간 IR**, 벽면 근접 | **0.18** | 0.45 | **야간 IR 도메인** (사람이 300px 로 또렷한데 못 봄) |
| `C00_115_0001` | 배회 | **야간 IR + 우산**, 비 | **검출 0개** | 0.40 | **야간 IR + 우산** |
| `C00_225_0001` | 배회 | **눈 + 우산**, 공원 | **검출 0개** | 0.40 | **눈 + 우산** |

### 어떻게 확인했나

1. 덤프에서 구역 안 박스를 세어 신뢰도를 봤다 → 전부 문턱 밑
2. 문턱을 낮추면 되는지 30편 전수 스윕 → **전부 나빠진다.** 지금 값이 고원 위에 있다
3. 그림으로 직접 봤다 → 사람이 눈에는 보이는데 모델이 못 본다
4. `conf 0.05` 까지 낮춰 다시 추론 → 그래도 0개 (255 · 115 · 225)

### 규칙 문제가 아니라는 근거

- 침입 문턱 스윕: `0.45`(94.74) = `0.40`(94.74) > `0.35`(91.23) > `0.30`(89.66) > `0.20`(79.31)
  세 편은 **어떤 설정에서도 창 안에 안 들어온다.** 275 가 터지는 33·49·68초는 정답(134)과
  100초 넘게 어긋나 오검+미검으로 두 번 깎인다.
- `hold` 1(70.18) · `corners` 1(84.21) 도 전부 나쁘다. 지금 조합이 격자 안에서 최고다.
- 배회 30편 중 **검출 0인 편이 딱 이 두 편뿐**이다. 나머지 28편은 검출이 충분하다.

### 공통점

**우산 · 야간 적외선 · 눈 · 원거리.**
배회 미검 2편은 **둘 다 우산을 쓰고 있다.** 우산이 머리와 어깨를 가려 사람 형태가 안 보인다.

## 5. 앞으로 필요한 것 — 우선순위

### 1순위. 야간 적외선 · 우산 · 눈 장면의 사람 손라벨 (가장 급함)

미검 5편 중 **4편이 여기 걸린다.** 그리고 이건 데이터로만 풀린다.

- 합법적으로 쓸 수 있는 공개 야간 IR 사람 데이터가 없다.
  `LLVIP`(가시광/적외선 각 15,488장)는 **비상업 라이선스라 학습 금지**,
  `FLIR ADAS v2` 는 라이선스 불명으로 미사용.
- 그래서 **KISA 연구개발 사람영상 825편을 직접 손라벨하는 것이 유일한 길**이다.

**어떤 편을 라벨해야 하나 (중요)**

| 우선순위 | 장면 | 왜 |
| :-- | :-- | :-- |
| **1** | **야간 적외선(흑백)** 사람 | 미검 3편(`255` · `115` + `275` 일부)의 원인 |
| **2** | **우산 쓴 사람** (비·눈) | 배회 미검 2편이 둘 다 우산 |
| **3** | **눈 오는 날** 사람 | `225` · `249` |
| 4 | 원거리 소형 사람(20~40px) | `249` · `275` |
| 5 | 주차장·지하주차장 등 **사람 없는 배경** | 손라벨 단독 모델이 여기서 오검을 냈다 |

지금 보유량: 사람 손라벨 **1,306프레임 / 71편**. 오늘 하루에 264 → 1,306 으로 5배 늘었다.

### 2순위. 손라벨이 실제로 효과가 있는지 확인 (돌리는 중)

**점수(F1)로 판단하면 안 된다.** 손라벨만 학습한 모델은 배경 다양성이 부족해 오검이 많아
40~50점이 나온다(실측: 배회 48.00 · 침입 53.85). 그 숫자로는 아무것도 알 수 없다.

**대신 이걸 본다.**

```
python scripts/zone_conf.py <가중치.pt>
```

미검 편의 **구역 안 최고 신뢰도**만 찍는다. `C00_255_0001` 이 `0.18 → 0.5` 로 오르면
손라벨이 작동하는 것이다. 오검은 COCO 를 섞으면 사라진다.

#### 결과 (2026-09-16 21:20) — 손라벨이 야간 IR 을 해결한다

오늘 만든 손라벨 셋(4,697장)만으로 학습해 재봤다. COCO 는 안 섞었다.

| 편 | 장면 | 배포 `person_v3` | **손라벨만** |
| :-- | :-- | --: | --: |
| `C00_255_0001` | **야간 IR** | 0.000 | **0.915** (문턱 0.45 통과) |
| `C00_249_0003` | 주간 설경 원경 | 0.189 | 0.000 |
| `C00_275_0001` | 야간 안개 원경 | 0.237 | 0.000 |

- **야간 IR 은 손라벨로 풀린다.** 배포 가중치가 `conf 0.05` 에서도 0개였던 편이 0.915 가 됐다.
  우연으로 보기 어려운 크기다.
- 나머지 둘이 0 인 것은 손라벨 모델이 **원경 소형을 못 보기** 때문이다.
  화면 전체 최고가 0.290 · 0.531 로 낮다. COCO(11.8만장)가 없어 일반 사람 검출력이 약하다.
- **그래서 다음은 COCO + 최신 손라벨 조합이다.** 둘 다 필요하다.

## 6. 내가(사용자가) 해야 할 일

### 지금 당장

1. **야간 적외선 · 우산 · 눈 장면 위주로 사람 손라벨 추가.** 위 우선순위 표 순서대로.
   장면 다양성이 중요하지 장수가 중요한 게 아니다.
   (근거: `wildfire_pos` 5.9만장이 +11.8, 눈·안개 증강 3,579장이 +8.1.
    반면 `azimjaan` 1만장은 0, AI허브 베이스는 25%로 줄여도 동점)
2. **사람 없는 배경 클립도 몇 편 라벨 대상에 올려 달라.** 주차장 · 지하주차장 · 빈 공터.
   지금 하드네거티브는 "손라벨이 있는 클립의 앞뒤 5장" 만이라 그 클립에 없던 장면은 안 들어간다.

| 무엇 | 왜 |
| :-- | :-- |
| **사전시험 방화 영상에 "연기만 나고 화염은 없는" 편이 있나** | 안내서 정의가 "연기 **또는** 화염" 이다. 지금 우리 구성은 연기를 안 본다(`smoke=1.1`). 그런 편이 나오면 못 잡는다 |

# 데이터 활용 대장 (데이터 관리 및 파이프라인 규약)
> **기준 파일:** `configs/datasets.yaml` (카테고리별 mode·media·gt·classes·use 제어)

---

## 1. 디렉토리 및 배치 규약

`data/` 디렉토리 하위에는 **`원본데이터/`와 `학습데이터/` 단 두 개만 존재**해야 합니다. (중간 그룹 폴더 생성 금지)

* **`data/원본데이터/` (수신 원본 보관)**
  * 폴더명 형식: `<출처>_<내용>` (접두어: `kisa_`, `aihub<번호>_`, `open_`)
  * 다운로드 및 압축 해제 위치. 어노테이션 파일도 원본과 함께 보관.
* **`data/학습데이터/` (YOLO 가공 데이터셋)**
  * 구조: `images/train`, `labels/train` (별도의 `val` 폴더는 생성하지 않음. 큐 러너가 600장 self-val 목록 생성)
  * **이미지 복제 금지:** 원본 데이터의 이미지는 심링크(Symlink)로 연결.
* **`data/학습데이터/손라벨/` (편집기 원천 JSON)**
  * `fire_labels.json`(초 단위), `person_labels.json`(0.5초/2FPS 단위).
  * `cls: -1`: "검토 완료, 객체 없음(배경)" 마커. 학습셋 빌더는 이를 배경으로 인지.

## 3. 학습 데이터 구축 규칙 (빌더: `build_trainset.py`)

* **우선순위 병합:** **손라벨 ➔ SAM 전파 ➔ 원본 정답(GT 어댑터)** 순으로 덮어씁니다. (동일 프레임 손라벨 존재 시 전파 무시)
* **프레임 추출 vs 심링크:** 영상 라벨은 해당 시각의 프레임을 추출(jpg)하고, 이미지 데이터셋은 원본을 심링크로 연결합니다.
* **하드 네거티브 자동 생성:** 손라벨이 존재하는 클립 구간의 앞/뒤 배경 프레임을 빈 라벨로 추가합니다. (사람: 직전/직후, 방화: 10프레임 버퍼 적용. 클립당 앞뒤 최대 5장)
* **검증셋(mAP) 분리:** 에폭 검증 시 누수를 막기 위해 학습 셋에서 샘플링하지 않고, **채점셋** 기반으로 빌드된 `evalset_<mode>`만 `val_set`으로 사용합니다.

## 4. 핵심 데이터 운영 원칙 및 제외(부적합) 데이터

* **데이터 통합:** 외부 데이터의 Train/Val/Test 분할은 의미가 없으므로 (중복이 아니라면) 전부 학습셋으로 합칩니다.
* **클래스 규약 엄수:** 데이터셋 통합 시 방화는 반드시 **`0=불, 1=연기`**로 매핑되어야 합니다.
* **음성(배경) 비율 제한:** 총 학습 데이터셋의 음성(배경) 이미지 비율은 **10% 이내**로 유지합니다. (초과 시 Recall 하락)
* **제외 및 재다운로드 금지 리스트:**
  * `aihub71953_다각도CCTV`: 영상당 단일 객체만 추적하여 KISA의 '다중 객체' 평가 규칙 검증에 부적합함 (삭제 유지).
  * `open_cctv_fire`: 박스(BBox)가 없는 분류형 라벨 데이터로 활용 불가.
  * 기존 합성/의사라벨 세트: 사람 객체 탐지 시 의사라벨을 학습에 사용하지 않기로 결정하여 일괄 폐기.

## 5. 원본 GT 가 틀린 편 (정정 목록)

원본 XML 의 `StartTime` 이 실제 발화 시각과 다른 편이 있다.
**원본데이터는 고치지 않는다.** 정정값은 `data/학습데이터/정답라벨/_gt_정정.json` 에 두고 도구가 그것을 먼저 본다.

| 클립 | XML | 실제 | 차이 | 확인한 것 |
| :-- | --: | --: | --: | :-- |
| `C050105_004` | 292s (04:52) | **221s** | -71초 | 220초 불꽃 없음 · 221초 발화 · 265초 소화 |
| `C050205_004` | 292s | **221s** | -71초 | 같은 장면 카메라 2 |
| `C050305_004` | 292s | **221s** | -71초 | 같은 장면 카메라 3 |

`C05<장소><카메라>05_<번호>` 라 카메라 3대가 같은 장면을 찍는다. 그래서 세 편이 같이 틀렸다.
같은 계열 `_002` `_003` 의 GT 가 222초인 것과도 맞는다.

### 어떻게 찾았나

두 가지가 같이 걸렸고, **연구개발 75편 중 딱 이 세 편만** 그렇다.

1. XML `Duration` 09:01 인데 실제 영상은 07:42 다(-78초). 나머지 72편은 2초 안에 맞는다.
2. 손라벨 박스가 0개다. 나머지 72편은 다 있다.

2번이 증상이다. `make_full.py` 가 라벨용 프레임을 **GT 기준**(`gt-7` / `gt` / `gt+8`)으로 뽑는다.
GT 292초면 285 / 292 / 300초를 뽑는데 불은 265초에 이미 꺼졌다.
그래서 라벨러에게 **불 없는 장면 세 장**이 갔고, 칠 것이 없으니 0개가 됐다.

### 손댄 곳

| 파일 | 무엇 |
| :-- | :-- |
| `data/학습데이터/정답라벨/_gt_정정.json` | 정정값과 근거. 새 편이 나오면 여기에 추가한다 |
| `data/학습데이터/정답라벨/C0501·C0503_004.json` | `start` 292 -> 221, `start_xml` 에 원래 값 보존 |
| `scripts/make_full.py` | 정정 파일을 먼저 본다. 이제 214 / 221 / 229 초를 뽑는다 |

`C050205_004` 는 `정답라벨` json 이 애초에 없다(연구개발 75편 중 정답라벨은 일부만 있다).

### 남은 일

세 편은 아직 **라벨이 0개**다. `make_full.py` 를 다시 돌려 프레임을 뽑고 손라벨을 쳐야 학습에 들어간다.
라벨 치는 것은 사용자가 직접 한다.

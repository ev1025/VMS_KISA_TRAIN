시험장에서 실제로 도는 구성이다. 2026-09-16 기준. 다른 곳과 어긋나면 **이 문서와 `results/BASELINE.json` 이 맞다.**

실행 파일은 `_kisa_port/tools/kisa_items.py` **하나뿐이다.** 항목마다 다른 파일을 쓰지 않는다.

```
python _kisa_port/tools/kisa_items.py --item <fire|intrusion|loitering|falldown> --rtsp <주소> --out <폴더>
```

## 2. 판정 규칙 본문

숫자만 보면 왜 그 숫자인지 모른다. 실제로 무엇을 세고 언제 터지는지를 적는다.
코드는 `_kisa_port/tools/kisa_items.py` 의 `FireJudge` / `FallJudge` / `IntrusionRule` / `LoiterRule` 이다.

### 공통

- 판정 시각(onset) 을 구한 뒤 **SA = onset + 지연**. 지연은 방화 10초, 배회 10초, 침입 0초, 쓰러짐 0초.
- 채점: 정답 시각 기준 `[-2초, +10초]` 안에 든 SA 하나만 정검.
- **창을 벗어난 SA 는 두 번 깎인다.** 오검 1 + 그 정답은 미검 1.
- `F1 = 2rp/(r+p) x 100`, 90 이상 합격.
- 주의: 실행 로그의 클립별 `오검` 표시는 그 클립의 모양만 적은 것이다. 합계는 위 규칙대로 오검·미검을 둘 다 센다.

### 방화 (FireJudge)

1. 0.5초마다 프레임 하나. 전체 + 4분할 + 중앙 = **6뷰**.
2. 6뷰 x 가중치 2벌 = 표본당 **12회 낱장 추론**. 그 표본의 값 = 12회 중 불 최고 신뢰도.
3. 불 >= **0.40** 이면 그 표본은 적중. **연기는 보지 않는다** (`smoke=1.1` 은 신뢰도가 넘을 수 없는 값이라 조건이 항상 거짓).
4. 최근 **20표본(10초)** 창에 적중이 **3회** 모이면, 그 창의 첫 적중 시각이 onset.
5. 클립별 분기는 없다. 모든 편이 같은 세 숫자(0.40 / 20 / 3) 를 쓴다.

### 쓰러짐 (FallJudge)

1. 0.1초마다 자세 추정 @1280, 신뢰도 상위 5명.
2. 중심 거리로 트랙 연결(0.8초까지 끊겨도 같은 사람).
3. 0.5초마다 트랙별 59차원 피처 하나를 쌓고, 최근 **20슬롯(10초)** 을 SeqNet 에 넣어 확률을 얻는다.
4. 확률 >= **0.755** 가 **연속 4창**이면 그 첫 창 시각이 onset. 여러 사람이면 가장 이른 사람.
5. 트랙이 끊긴 뒤에도 0벡터를 계속 이어 붙인다. 쓰러진 뒤 검출이 끊기는 패턴이 바로 여기서 터진다.

### 침입 (IntrusionRule)

1. 0.5초마다 3x3 타일 @960 사람 검출. 타일 NMS 의 **부분검출 억제는 끈다**. 트래커가 ID 를 붙인다.
2. 사람 상자 네 꼭짓점 중 **3개**가 구역 안이면 진입.
3. 같은 ID 가 **2표본 연속** 진입이면 그 사람의 진입 시각을 적는다. 끊김은 **2표본**까지 봐준다.
4. 가장 늦은 진입 시각을 들고 있다가 **24초** 동안 새 진입이 없으면 확정.
5. onset = **마지막으로 들어온 사람의 진입 시각** (확정 시각이 아니다).

### 배회 (LoiterRule)

1. 0.5초마다 전체 프레임 @640 사람 검출 + BoT-SORT ID.
2. **발끝**(상자 하단)이 구역 안이면 체류 누적. 끊김은 **6표본**까지 봐준다.
3. 체류가 **6초**를 채우면 배회자. 그 사람의 진입 시각을 적는다.
4. 마지막 배회자가 생긴 뒤 **5초** 기다려 확정. onset = 마지막 배회자의 진입 시각.
5. 다만 아래 **넷을 모두** 만족하면 5초를 넘겨 온 사람도 "마지막 사람" 으로 받는다(늦은 일행).
   - 지금 고른 사람이 **아직 구역 안** (1초 안에 목격)
   - 앞 배회자와 **20초 이내**
   - 구역 인원 **3명 이하**
   - 그 사람이 **방금 도착** (진입 시각 = 구역에 처음 들어온 시각)

## 3. 쉽게 틀리는 곳

## 7. 남은 위험 (2026-09-16 기준, 아직 확인 안 한 것)

| # | 무엇 | 왜 위험한가 | 확인 방법 |
| :-- | :-- | :-- | :-- |
| 1 | **실시간으로 돌려본 적이 없다** | BASELINE 네 항목 전부 `FileSource` 로 잰 값이다. 파일은 느리면 그냥 오래 걸릴 뿐 프레임을 안 흘린다. RTSP 는 흘린다 | `--rtsp` 로 4항목 재측정 |
| 2 | **침입이 실시간보다 느리다** | 영상 9917초를 처리하는 데 12582초(0.79배). 3x3 타일 = 표본당 9회 추론이라 다른 항목의 9~13배 무겁다 | GPU 비었을 때 1편 단독 계측 |
| 3 | **방화가 연기를 안 본다** | `smoke=1.1` = 연기 조건 영구 거짓. 불꽃이 안 보이고 연기만 나는 편이 시험에 나오면 전편 미검 | 사전시험 영상 구성 확인 |
| 4 | **방화 100.00 의 근거가 얇다** | 10편뿐, LOOCV 80.00, 창 여유 0.5초가 2편. 안전 구간은 90~94.74 | 편수 늘리기 |
| 5 | **침입과 배회가 다른 경로다** | 같은 "구역 안 사람" 인데 가중치도(v3/v2) 해상도도(960타일/640전체) 추적기도 다르다. 두 벌을 따로 유지해야 한다 | 한쪽으로 합쳤을 때 점수 확인 |

| 7 | **침입에 늦은 일행 규칙이 없다** | 배회는 이 규칙으로 93.10 -> 96.55 가 됐다. 침입은 24초 단순 대기뿐인데 미검이 3편 남아 있다 | 미검 3편이 다수 사건인지 확인 |
